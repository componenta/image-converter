# Componenta Image Converter

Конвертация статических изображений в выбранный формат. [English documentation](README.md).

## Установка

```sh
composer require componenta/image-converter
```

Требуются PHP 8.4+, расширения GD и EXIF, Componenta Config 4 и MIME Type Detector 2.

## Использование

Поставщик конфигурации регистрирует `ImageConverter` и четыре встроенных обработчика GD. Получите сервис из контейнера или создайте его, передав `MimeTypeDetectorInterface` и коллекцию обработчиков.

```php
use Componenta\Image\ImageConversionOptions;

$image = $converter->convert($source, 'webp', new ImageConversionOptions(quality: 85));
$png = $converter->convert($jpegSource, 'png', new ImageConversionOptions(compressionLevel: 7));
```

Источник — строка с байтами изображения (не путь к файлу) либо поток PSR-7. Результат `ConvertedImage` содержит доступные только для чтения свойства `content`, `mimeType`, `extension` и вычисляемый размер `size` в байтах. Результат требует непустых байтов, конкретного MIME-типа изображения без параметров и допустимого расширения без начальной точки. MIME-тип и расширение приводятся к нижнему регистру. Для известных MIME-типов с зарегистрированными расширениями расширение должно соответствовать стандартному каталогу MIME Type Detector. Пользовательский MIME-тип без записи в каталоге может задавать собственное допустимое расширение. Эти проверки не подтверждают корректность самих байтов и не разрешают путь к файлу; правила хранения и выдачи определяет приложение.

## Форматы и параметры

| Целевой формат | Исходные форматы |
| --- | --- |
| JPEG | PNG, WebP, AVIF, BMP |
| PNG | JPEG, WebP, AVIF, BMP |
| WebP | JPEG, PNG, AVIF, BMP |
| AVIF | JPEG, PNG, WebP, BMP |

Обработка без смены формата относится к пакету image-compressor.

Доступность форматов зависит от сборки GD. Метод `supports()` учитывает исходный MIME-тип и наличие кодеков. Метод `canConvert($source, 'webp')` проверяет возможность выбора обработчика и ограничение размера входных данных, а не полную корректность изображения.

- `quality` — качество JPEG, WebP и AVIF, от 0 до 100.
- `compressionLevel` — уровень сжатия PNG, от 0 до 9; не влияет на визуальное качество.
- `avifSpeed` — скорость кодирования AVIF, от 0 до 10; меньшие значения повышают степень сжатия.

Значения по умолчанию: JPEG — 82, WebP и AVIF — 80, PNG — уровень 6, скорость AVIF определяется GD. Неподдерживаемые параметры отклоняются.

## Потоки и ограничения ресурсов

Перематываемый поток читается с начала; его позиция восстанавливается при успешном выполнении и ошибке. Если само восстановление не удалось, операция и предварительная проверка выбрасывают `ConversionStreamPositionRestoreException` (подтип `ConversionException`); позиция больше не гарантируется. Исключение сохраняет причину ошибки восстановления и исходную ошибку чтения в свойстве `readFailure`. Неперематываемый поток читается один раз с текущей позиции, а предварительная проверка возвращает false, не потребляя данные. Оркестратор передаёт детектору и обработчику один набор байтов, в том числе для пользовательских реализаций.

По умолчанию `ImageConversionLimits` ограничивает входные данные 32 МиБ, разрешение — 16 000 000 пикселей, ширину и высоту — 8192 пикселями, результат — 64 МиБ. Зарегистрируйте объект ограничений в контейнере зависимостей, чтобы штатные фабрики настроили оркестратор и встроенные обработчики совместно. При ручной сборке передайте один объект ограничений оркестратору и каждому обработчику: оркестратор ограничивает объём байтов, обработчик — размеры изображения и собственные ограничения байтов. Самостоятельно созданный или переопределённый обработчик сохраняет собственные настройки. Встроенные обработчики проверяют размер и заявленное разрешение до декодирования и ограничивают объём сохраняемых выходных данных. Оркестратор также отклоняет слишком большой результат пользовательского обработчика; такой обработчик самостоятельно ограничивает декодирование и выделение памяти.

Структурная проверка AVIF отклоняет повторные блоки типа файла, метаданных и свойств элементов и ограничивает каждый контейнер 32 767 свойствами (максимальный представимый индекс свойства).

Ограничения не гарантируют точный предел потребления памяти и времени нативными кодеками. Для недоверенных загрузок дополнительно нужны проверка входных данных, изоляция процессов и ограничение ресурсов.

## Корректность изображения и ошибки

Встроенные обработчики работают со статическими изображениями. GIF, APNG с признаком анимации, анимированный WebP и AVIF с заявленным признаком последовательности `avis` не поддерживаются. Входной JPEG должен содержать корректную последовательность внешних маркеров до EOI; усечённые данные отклоняются, даже если GD способен их восстановить. Дополнительные данные после EOI допускаются и удаляются при перекодировании. Это не является полной проверкой коэффициентов сжатия. Ориентация JPEG из EXIF применяется до перекодирования. При преобразовании в JPEG прозрачность заменяется белым фоном. Палитра PNG не преобразуется без необходимости. GD не гарантирует сохранение метаданных, цветовых профилей, расширенного динамического диапазона и большой глубины цвета. Качество AVIF в GD также влияет на квантование альфа-канала: при низком качестве значения прозрачности могут изменяться. Отдельный режим сохранения альфа-канала AVIF без потерь недоступен; компрессор отклоняет 16-битный PNG. Заголовок результата проверяется на формат и размеры, но повторное полное декодирование результата при каждой операции не выполняется.

Контейнер AVIF с блоком `moov` без явно заданной основной марки `avif` также отклоняется: libavif может выбрать дорожку вместо основного статического изображения в зависимости от порядка блоков.

При обработке AVIF отклоняются связанные с основным цветовым изображением ненейтральные преобразования отображения (`irot`, `imir`, `clap`, `pasp`): GD не применяет поворот, отражение, кадрирование и изменение пропорций пикселей при декодировании. Нейтральные и неиспользуемые свойства, а также независимые преобразования других элементов (например, миниатюр) допускаются. Это исключает незаметное изменение геометрии при перекодировании.

Ошибки обработки представлены `ConversionException`. Некорректная регистрация или настройка ограничений вызывает `InvalidArgumentException`. Неожиданные программные ошибки не подавляются.

## Расширение и интеграция

Реализуйте `ImageConverterInterface` для пользовательского обработчика. Реализуйте `ImageConversionTargetsProviderInterface` для автоматической регистрации псевдонимов либо укажите их явно в `addConverter()`. Конфликт регистрации разных обработчиков одного нормализованного псевдонима отклоняется целиком. Для встроенных форматов допустимы короткие имена, расширения и MIME-типы (`jpg`, `jpeg`, `image/jpeg`). Все зарегистрированные псевдонимы связаны с одним каноническим выходным форматом. При нескольких пользовательских псевдонимах укажите канонический MIME-тип (например `special`, `image/x-special`); единственное короткое имя без объявления формата подразумевает `image/<имя>`. Объявленный или уже зарегистрированный формат обработчика применяется и к новым явным псевдонимам. Один обработчик фиксированного формата нельзя повторно зарегистрировать для другого канонического формата. MIME-тип результата должен соответствовать операции; пользовательский обработчик отвечает за корректность байтов.

Поставщик `Componenta\Image\ConfigProvider` указан в метаданных Composer для автоматического обнаружения. Фабрики используют зарегистрированный детектор или создают `FinfoDetector`. Для преобразования исключительно в WebP интерфейс `ImageConverterInterface` зарегистрирован как псевдоним `GdWebPConverter`.

## Проверки

```sh
composer test
composer analyse
composer bench
```

Для измерений нужна сборка GD со всеми встроенными кодеками. PHPBench использует воспроизводимые синтетические изображения на 1, 4 и 12 Мп (в пределах ограничений), сравнивая строки и потоки. Переход с предыдущей версии описан в [UPGRADE.md](UPGRADE.md).

Процесс `Compare performance` сравнивает v1.0.1 и новую версию на одном исполнителе PHP 8.4 с эквивалентными параметрами кодеков и тремя изолированными измерениями на сценарий. Операции, не поддерживаемые v1, исключаются; потоки измеряются на 1 Мп. PHPBench показывает пик памяти под управлением PHP, а не полное потребление памяти процесса.
